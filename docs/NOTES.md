# 设计笔记

这份笔记记录的是故事设定、已经定下来的事、第一轮的反馈和没来得及做的灵感。以后接着做的时候，先读这一份。

---

## 一、故事内核

有一伙神秘的人，攒下了一笔钱，想要撬动整个世界的经济。他们已经对金融市场构成了威胁，于是有人开始追查他们背后的那个人。

- 访客就是那个**侦探**。打开页面，等于骇进了这伙人的内部系统。
- 系统里能查到**已知成员**（Luna、Hound、武器大师……）、他们的职责、最近的动作，还有一些**未解锁的空位**：只有一个不稳定的虚影，头像是未知的。以后每加一个成员，就点亮一个位置。
- 线索一条接一条，像解谜一样**层层递进**，而且全都指向同一个人。
- 那个人的形象是**一片漆黑**。点他的头像，名字是被涂掉的；再点那个被涂掉的名字，**警报一层层叠上来，铺满整个屏幕。**
- 核心感受是**螳螂捕蝉，黄雀在后**：你以为自己想尽办法才看到的东西，其实都是他想让你看到的。

**最重要的一条：** 形式不拘泥于某种风格，比如赛博朋克。目的是把这个概念传达出来，而抓人眼球的地方，要放在"表达形式"上。

---

## 二、核心概念：蜜罐（Honeypot）

"蜜罐"是安全领域的真实术语：故意搭一个看起来有漏洞、很值钱的系统，把入侵者引进来，然后在暗处看着他。

**整个前端就是一个蜜罐。** 访客以为自己在骇入，到结局才知道，这个系统就是为他搭的。

围绕这个概念，已经想好的伏笔有下面几条。它们第一遍看像小 bug，看完结局再回想，全是线索：

- 每份档案的"最后修改时间"，都在访客打开它之前几秒。说明文件是刚为他准备好的。
- 破解进度条还没走完，`ACCESS GRANTED` 就先跳了出来。说明门本来就开着。
- 截获的聊天记录里，最后一条消息的时间是"刚刚"，内容是：「让他进来。」
- **故障特效有剧情意义**：故障代表入侵信号不稳定，越靠近幕后之人，干扰越强。可到了结局那一刻，**所有故障突然消失，画面变得完美稳定**，因为那从来就不是干扰，连接一直是被故意维持着的。
- **结局加一刀**：警报铺满屏幕之后，屏幕清空，系统把访客自己的足迹回放给他看，比如"21:47 接入。先打开了 Luna 的档案，在武器大师的休眠记录前停留了 38 秒……"。只用浏览器本地已经知道的信息，不收集、也不上传任何数据。
- **回访彩蛋**：第二次打开的人还没开始骇入，屏幕上就先出现一行字：「你又来了。」（用 localStorage 实现）

## 三、已经定下来的规则

### 语言：按"谁在说话"来分

- **系统的声音用英文**：状态、代码、标签都用大写等宽字，比如 `STATUS: DORMANT`，冷，有机器感，主要当纹理用。
- **侦探的笔记用中文**：推理、描述、结论，凡是需要读者真正读懂的内容都用中文。
- **代号保持原样**：Luna、Hound、武器大师，不翻译。
- **幕后之人最后那一句话用中文**：整场系统都在说冷冰冰的英文，最后一句突然换成母语对你说话。
- 不要做成"已知成员 / KNOWN MEMBER"那种每个词都中英并排的双语标签，看多了会显得廉价。

### 标题：留白

原来的暂定名「黑箱」太普通了，另外想的几个名字也都不够好，所以干脆留白。标题的位置可以放一道涂黑的条，连名字都被隐去了，这本身就是那个神秘人的风格。

### 颜色：红色只留给"线"

以 B 的黑色电影为基调：近黑、冷灰，加一点侦探台灯的琥珀色。**红色只用在两个地方**：连接线索的红线，以及结局的警报。线索线和警报用同一种红，所以红色从头到尾只讲一件事：一切都指向他。

### 数据：只做样子

原项目已经停用，交易数据只需要"有这个概念"，用静态数据做成"截获的交易记录"就够了。**交易所的私钥绝对不能放进前端**，任何人按一下 F12 就能拿走。以后如果真要接实时数据，必须加一个只读 key 的后端。

## 四、第一轮反馈（三个切片）

| 方向 | 反馈 | 学到的 |
|---|---|---|
| **B 黑色电影** | 最好。"五个人六个影子，鼠标移上去影子就闪开"最有感觉 | 概念靠观众**自己发现的异常**来传达，比任何旁白都有力 |
| A 剪纸片头 | 剪辑思路还可以，但画得不太行（尤其是"壹贰叁"），整体像十年前的短视频片头。"已知成员 3 · 身份不明 2"那个名单片段不错 | 文字色条 + 每句话配一个图标 + 定格抖动，这套模板化的动效语言已经过时。代码画的具象物件（地球、塔、硬币）撑不起质感 |
| C 预告函 | 开场拖沓，太逐字照着原话来了。「选择调查对象」界面不错 | 不要把原话一句一句变成字幕。给的是概念，表达形式可以随意 |
| 共同 | 三个版本里的"成员名册"都受欢迎：卡片、选角界面、未解锁的空位 | 名册的"游戏感陈列"是加分项 |

**一句话原则：少说，让人自己发现。**

## 五、下一步的方向（还没做）

### 分镜式叙事

很多成品游戏讲剧情，都是先蹦出一个片段，像漫画的一格分镜，然后逐一展开一段剧情。这正是想要的样子。

- 参照《致命框架》（Framed）：黑色电影风，整个故事靠漫画分镜推进，玩法是**重新排列分镜的顺序**，讲的也恰好是一个神秘人被追捕的故事。反馈是"不错"。
- 适合代码实现的是高反差的剪影和光影、大色块、字体、UI 界面、局部特写（眼睛的剪影、手里的手机、墙上的影子）。代码不擅长的是细致的手绘插画，这部分要么避开，要么另外找素材。

### 用颜色讲进度（受 GRIS 启发）

GRIS 的画面反馈是"真的很唯美"。它的特别之处在于**颜色本身在讲故事**：世界一开始是灰的，每过一章，找回一种颜色。

可以借鉴的思路是：刚骇进去的时候，他的世界是一片灰。访客每揭开一个成员，画面里就多一样东西，一种颜色、一道光、一个声音……等所有颜色都找回来，才发现这幅画是他早就画好的，只是等着你来一笔一笔填满。

能学的是 GRIS 的**骨架**：色彩克制、大片留白、渺小的人放在空旷的空间里、让颜色推进剧情。它的手绘水彩质感，代码做不出来。

### 结构草案

1. **开场极短**：不逐句念旁白。
2. **嫌疑人列队作为枢纽**（沿用 B）：点一个人，就抽出他的档案卡（借鉴 A 名单卡片的陈列感），然后进入他那一层。
3. **每一层都藏一个"第六个影子"式的异常**，让访客自己去发现。
4. 这些异常一层层累积，全都指向那个没有名字的人。
5. **结局**：漆黑的头像 → 被涂掉的名字 → 警报铺满屏幕 → 故障全部消失，画面完美稳定 → 回放访客自己的足迹 → 最后一句中文。

### 最早的构思里，还没用上的点子

- **网络联动**：用真实网速驱动故障强度。Clash 的控制接口只在本机才有，而且浏览器会拦截公网页面访问 localhost，所以 Clash 联动只能当作本机彩蛋；给所有访客用的版本，靠浏览器自己测延迟。
- **截获的手机**：一开始是不稳定的虚影，慢慢聚成实体。打开是一个类似即时通讯软件的群聊，成员头像都是未知的。
- **成员档案**：职责、最近一次动作（比如"最近一次下单在三天前"）、状态（比如 `DORMANT`：休眠，不等于退役）。
- **交易记录**：持仓、浮盈浮亏、本金和杠杆、币种。只做 UI，用静态数据，刷新频率无所谓。
