# 技术细节

纯静态站点：HTML + CSS + 原生 JS，动画用 [GSAP](https://gsap.com/) 3.15（核心 + Draggable + Inertia），没有构建步骤，没有外部网络依赖。以下数字都是在 Chrome（macOS）上实测的。

## 1. 总体结构

```
v2/index.html   首页的结构和样式（HUD、ENTER 键、光效、脚下阴影…）+ 撕开转场的代码
v2/scene.js     首页场景：分层、红线物理、分镜墙、视差、微动、墙面彩蛋
v2/hub.js/css   嫌疑人列队页
v2/sfx.js       音效（WebAudio 合成）
v2/panels.js    30 张分镜的清单 {文件, 宽高比}（由 tools/split-sheet.py 生成）
```

首页和列队页在**同一个文档**里：列队页是一个盖在首页上面的 `<section id="hub">`，转场结束后首页被隐藏。入口 `window.BB.openHub()`，首页角色通过 `window.Scene.who` 告诉列队页默认打开谁。

**统一的坐标系：** 首页的所有东西（墙、人物、贴纸、红线、灯光）都放在一块 **1672×941** 的"场景画板"里（和墙面图的像素尺寸一致），整块按 `cover` 缩放。这样红线、人物、分镜的位置用画板像素写死，换屏幕尺寸只缩放，不会错位。窄屏会裁掉左右两边，人物始终居中，贴纸被收进可见范围。

## 2. 首页场景的图层

从后到前：

| 层 | 内容 | 备注 |
|---|---|---|
| `bgPar`（背景组） | 墙面底图、三个光斑（左灯、右灯、中央光晕）、**远层**分镜墙 | 视差幅度最小 |
| `midPar`（近层组） | **近层**分镜、四张海报、装饰贴纸 | 视差幅度稍大 |
| `figPar`（人物组） | 投影、倒影、脚下接触阴影、背光、人物本体 | 内部再套一个 `fig-wrap` 做呼吸 |
| 红线（SVG） | 一条路径 + 末端的小图钉 | 见 §3 |
| `dustPar`（灰尘组） | 一块 canvas：70 粒灰尘 + 右灯光锥里的 34 粒尘埃 | 视差幅度最大 |
| 屏幕空间 | 暗角、胶片颗粒、HUD、ENTER 键 | |

**视差：** 四个组各自用 `gsap.quickTo` 跟随鼠标，幅度 6/4、10/6、14/8、26/14 像素（x/y），时长 1.3 秒。

**分镜墙：** 画板上取 8×5 的网格，每格加随机抖动，剔除头顶光晕的椭圆、中间人物的竖条、两盏灯的光锥，剩下的格子随机排序后取 22 个；每个格子从 30 张分镜里抽一张。55% 的分镜进"远层"（亮度更低、尺寸更小，挂在背景组），其余进"近层"。三分之一用一小条胶带粘着。尺寸、角度、位置都带随机。

**海报：** 每张是 `.pst > .sw > .pin > (影子、海报、胶带)` 四层包装。外层负责"啪"地贴上去（缩放 1.7→0.965→1，弹性回弹，影子收紧，墙面轻震，胶带随后冒出），中间负责微风里的轻晃，最里层负责鼠标悬停时翘起。**一个元素只让一个动画系统管**（见 §9）。

**人物接地：** 三个角色的脚高低不同（其中一位的左脚明显抬着），所以每个角色**每只脚**有自己的坐标，每只脚两层阴影（人物后面的软影 + 压在鞋底边缘上的暗边），两脚之间再放一块共用的暗区，让两只鞋读成踩在同一片地面上。另外有投在地上的影子、地面倒影、贴地的薄雾。

**光效：** 全部是 CSS，`mix-blend-mode: screen`：一道从上往下的光束；两层方向相反、缓慢旋转的光芒（`repeating-conic-gradient` 加径向遮罩，160 秒和 240 秒一圈）；一团呼吸的泛光；一道横向光斑；右灯的星芒和一道斜着打出的光锥（光锥里有尘埃缓慢飘过）。

**随机角色：** 每次打开从三人里随机选一个，用 `localStorage` 记住上一次的，不连续重复；`?c=` 可以强制指定。

## 3. 红线：一根真的绳子

首页的红线是 **Verlet 积分**的绳子，在场景画板坐标里模拟，每帧渲染成一条 SVG 路径。

| 参数 | 值 |
|---|---|
| 节点数 / 每段长度 | 28 / 33 px |
| 重力 | 2600（px/s²，以子步长积分） |
| 子步 / 约束迭代 | 每帧 2 个子步，每个子步 14 次距离约束 |
| 阻尼 | 每步速度 ×0.993 |
| 地面 | 斜的：`y = 886 + max(0, 940 − x) × 0.17`（越靠近观众越低）；碰地时水平速度保留 78%，模拟摩擦 |
| 鼠标拨动 | 半径 52 px 内的节点被鼠标的移动量推动，力度随距离衰减，垂直方向打 7 折 |

- **一头钉在手上**：每次约束迭代先把第 0 个节点固定到"手"的位置（手的位置是人物图里标的一个比例坐标，随人物的呼吸和视差一起动）。
- **放线：** 鼠标悬停或聚焦到 `ENTER`，绳子每段长度向 `距离 × 1.035 / 27` 过渡（"放线"），末端按权重被拉向按键并最终被钉住（权重超过 0.98 时末端固定），中间因为多出来的 3.5% 自然下垂。移开则慢慢收回。触屏没有悬停，3.2 秒后自动拉过去。
- **渲染：** 28 个点用 Catmull-Rom 样条转成三次贝塞尔路径。路径字符串含 `NaN` 时整帧丢弃（页面刚排好版、或被浏览器暂停恢复的第一帧可能出现无效坐标）。
- **一个教训：** 一开始红线是"线头追着鼠标"，被评审者指出"怪"：没有因果，凭什么这个东西对我的鼠标有反应。现在线只对 `ENTER` 有反应。

## 4. 撕开转场

点击 `ENTER` 后，**不是另外冒出一条线来切，而是你一直看着的那根红线自己把屏幕撕开。**

1. 把绳子的末端立刻拉紧（`pull`，0.35 秒），取这一刻绳子 28 个节点的屏幕坐标（`Scene.threadScreen()`）。
2. 把两端沿切线方向延长到屏幕之外，形成一条贯穿屏幕的折线；奇数序号的点加 ±4 px 的随机抖动，作为**撕边**。
3. 把当前整页（`<main>`）用 `cloneNode(true)` 复制成两份，各自用 `clip-path: polygon(...)` 只留折线的一侧。**两半共用同一条折线**，所以严丝合缝。
4. 原来的红线先隐藏，免得被复制时劈成两半；画一条和切口完全重合的红线盖在最上面，先"嗡"地震一下再淡出，同时白光一闪、一声低沉的音效。
5. 两半分别沿折线的法线方向滑出屏幕（各带 ±3° 旋转），动画进行到 0.42 秒时调用 `BB.openHub()`，列队页从下面显出来。

**两个细节：**
- `cloneNode` **不会复制 canvas 的像素**，所以复制出来的两半里，灰尘画布要用 `drawImage` 把当前帧画上去。
- 复制是整页的，成本在那一刻集中出现，是目前转场里唯一偶发的卡顿（见 §6）。

## 5. 美术素材流水线

### 5.1 出图

用图像模型（gpt-image-2），通过 Codex 命令行无界面调用：

```bash
codex exec --skip-git-repo-check -C <工作目录> --ephemeral \
  "\$imagegen <提示词>. Save the final image as <绝对路径> and tell me the exact path." \
  -i <参考图1> -i <参考图2> < /dev/null
```

几条踩出来的规则：
- **提示词放在 `-i` 前面**，否则 `-i` 会把后面的提示词也当成图片文件吞掉。
- 后台跑要**关掉标准输入**（`< /dev/null`），不然启动时会卡住等输入；多个任务可以并行。
- **同一个角色保持一致**：先出一张"四人并排"的合影锁定画风，之后每次出单人图都把它作为参考图传进去。
- **想要透明就先画在纯品红 `#FF00FF` 上**，不要让模型直接画透明或白底（见 5.2）。
- 要改图（去掉红线、去掉电视、补头顶）用**编辑**：把原图作为参考，写"保持其余一切不变，只改……"。
- 海报里的字要逐张核对（拼写、中文），模型偶尔会错。
- 一个任务超过 8 分钟没有产出文件，杀掉重发，比等更快。

### 5.2 抠图：品红底 + 色键（`tools/chroma-key.py`）

最初用的"从边缘泛洪、把和边缘相连的近白色当背景"的抠法，**去不掉头发丝之间被圈住的白色缝隙**，人物像戴了一顶白帽子。试过的几种办法：

| 办法 | 结果 |
|---|---|
| 最初的泛洪填充（从边缘把近白色当背景） | 头发缝隙里的白色去不掉 ✗ |
| macOS 自带的前景分割（`vision-cutout.swift`，Vision 框架） | 轮廓很好，但头发里残留零星白点 |
| 让模型直接输出带透明通道的 PNG | 干净，通道范围 0–254；但依赖模型这次听话 ✓ |
| **画在品红底上再色键** | 缝隙也是品红，所以抠得干净；可批处理 ✓✓ |

色键公式：对每个像素算 `m = min(R, B) − G`（背景纯品红约 240–255，黑白灰为 0，红色点缀也为 0，所以人物里的红色不会被误抠）。先从**画面边缘**量出背景的 `m` 中位数 `bg`（GPT 画的"纯品红"每处略有差别），阈值取 `bg − 30`：`m` 大于它的当背景；`m ≤ 6` 的完全不透明；中间的算半透明 `α = (阈值 − m) / (阈值 − 6)`，并把混进去的品红**反混合**减掉，去掉边缘的品红色边。

### 5.3 一张合集拆成许多张（`tools/split-sheet.py`）

让模型在品红底上画一张"六个小分镜的合集"，色键之后，用连通域找出互相分开的块（先轻轻膨胀 3px，把一个分镜里的碎片连起来；太多会把靠得近的两张粘成一张），各裁成一张透明 WebP，并生成 `panels.js` 清单。五张合集 → 30 张分镜。

### 5.4 字体

只带用到的：Anton、Space Mono 的拉丁字母，以及 Noto Serif SC 600 的 **581 个字符**的子集（页面里所有出现过的汉字），一共 **146 KB**。页面加了新汉字时运行 `python3 tools/build-fonts.py` 重新生成。

## 6. 性能：从 23 帧到 60 帧

症状：一打开页面就卡。**先量，再改。**

### 6.1 方法

`tools/perf.mjs`：用 Chrome 调试协议（CDP）打开页面，按 **Retina 分辨率**（1440×900 @2x）、开 GPU，页面稳定后用 `requestAnimationFrame` 连续采样 3.5 秒，报告帧率、p50/p95/最差帧时间、超过 33 毫秒的帧数，以及每帧的 JS、样式重算、布局耗时（`Performance.getMetrics`）。然后**逐项注入 CSS/JS 关掉怀疑对象**，看帧率怎么变。

### 6.2 结果

| 状态 | 帧率 | p95 | 最差一帧 |
|---|---|---|---|
| 修复前（Retina） | **23 fps** | 200 ms | 316 ms |
| 只加 `will-change: transform` | **60 fps** | 16.8 ms | 16.8 ms |
| 1920×1080 @2x | 60 fps | 16.7 ms | 16.8 ms |

逐项关闭实验（修复前）：关掉胶片颗粒层，卡顿尖峰（p95）从 133 降到 50 毫秒；关掉分镜和海报上的滤镜，从 30 帧跳到 60 帧；光效、灰尘、暗角、红线几乎不花钱。

### 6.3 根本原因

页面里有 **20 多个带 `drop-shadow` / `blur` / `brightness` 滤镜的元素**，而它们的祖先每一帧都被 GSAP（JS）改一次 `transform`（视差、微风里的轻晃、人物呼吸）。**JS 驱动的 `transform` 如果元素没有被提升成独立的合成层，浏览器每帧都要把这块区域重新绘制，里面的滤镜也跟着重算。**

修复只有一句：

```css
.lyr, .pst, .psw, .pnl, .fig-wrap { will-change: transform; }
```

让浏览器把这些"每帧在动"的元素当成独立的 GPU 贴图，之后只挪动贴图，里面的内容和滤镜不再重画。

**代价与取舍：** 每个合成层都占显存。所以只给**确实在动**的元素开（4 个视差组、人物组、海报和分镜），而不是给所有 `.L` 全开。

### 6.4 顺手做的几项

- **胶片颗粒层**：以前 `inset: -50%`（四倍屏幕大）还叠 `mix-blend-mode: multiply`，Retina 下是一张 5760×3600 的纹理，每帧混合一次。改成只比屏幕大一圈（`inset: -6%`）、普通叠加。
- **冷启动**：在一个全新的浏览器里，DOM 就绪要 **2203 毫秒**，因为 GSAP 三个脚本和字体样式表都来自外网（脚本放在页面末尾，但场景是脚本搭的，所以这 2 秒里是空壳）。**自托管**之后降到 **161 毫秒**，load 事件从 2278 毫秒降到 323 毫秒，**外网请求归零**，不再受访客网络（或某些网络环境下外网被拦）的影响。
- 字体子集化（§5.4）：之前 Google 返回的是几十个分片。
- **分批加载（在真实网速下才看得出的问题）：** 本地没有带宽限制，量出来一切都很快；但把网络限成 5 Mbps / 60 ms、关掉缓存再量，**墙 4.2 秒才到，人物要 7 秒才到**（几十张图同时抢带宽，最重要的人物反而最后到），而开场动画在 1 秒左右就开始放，于是先看到一片黑，再看到空框"啪"地贴上去，图后来才冒出来。改法：
  1. 只有墙和人物先请求（约 0.6 MB），墙还用 `<link rel="preload" fetchpriority="high">`；
  2. 它们到了才宣布 `Scene.ready`，首页开场（HUD、淡入）才开始放；同时放行海报、胶带、装饰（约 0.9 MB）；
  3. 海报到了（最多等 1.8 秒）再放行 22 张分镜，**每张到货就自己"啪"地贴上去**，网速慢时变成一张张陆续贴上，而不是一片空框；海报到齐后再拍上墙；
  4. `hub.js` 延后加载（它一启动就请求 4 张共 1.6 MB 的大海报）：首页稳定后 2.5 秒、或鼠标靠近/点击 `ENTER` 时才取，点得再快 `openHub()` 也会等它加载完；
  5. 墙和人物还在路上时显示一个极简的启动画面（`CONNECTING` 加一条红线扫过），加载很快（不到 0.4 秒）就根本看不见。

  限速 5 Mbps 实测：**人物到货 6.95 秒 → 1.47 秒；墙 4.19 秒 → 1.75 秒；开场 1.75 秒开始，此时关键图都已就位。** 不限速时仍是 60 帧。

### 6.5 还在的问题

- 点 `ENTER` 撕开的那一刻（整页复制），平均 58–59 帧，但会有**一帧 50–150 毫秒**的停顿。
- 图片总量：首页约 4.3 MB、42 个请求（海报和分镜已经分批、列队海报已经延后，见上）。墙面图 470 KB 还可以再压一点；列队页的四张海报（1100 px 宽，每张约 400 KB）可以再瘦一些。

## 7. 嫌疑人列队页

由 GPT 的编码模型施工（流程见 [`PROCESS.md`](PROCESS.md) §4，任务书、第一轮意见、决定文档在 [`docs/hub-design/`](hub-design/)）。

**说明：** 下面的行为里，**切换、第四个人解锁、`NO SIGNAL`、`MODIFIED → OPENED` 差 3 秒、翻角开关、窄屏无横向溢出**我在真浏览器里实测过；**拖动的边界、`prefers-reduced-motion` 的降级、竖屏滑动手势、红线尾巴图钉的具体动作**是按设计要求实现的，没有逐项实测。

- **布局：** 同一张墙（轻微放大 + 压暗）作背景，一张大海报是主角，两张小海报，一张内容驱动高度的档案卡，底部 `01/02/03` 编号键（B 风格斜切键），`BACK`。点小海报会和主角互换。
- **档案卡：** 编号、状态标签、`CODENAME / ROLE / MODIFIED`、中文笔记。字段先被涂黑条盖着，选中后一条条退开；`EXAMINED` 的小印在底部预留的页脚里，不会盖住笔记。桌面上可以从顶部的抓手拖动（有边界，不会盖住 `BACK` 和编号键）；竖屏上不能自由拖，只有一个翻角的小开关。
- **状态模型：** 切换是"最新一次选择获胜"（每次选择带一个令牌，过期的动画回调不会改新状态）；"已读"要等涂黑条全部退完才算数；三份档案**都读完**，第四个人才出现，并且只出现一次，之后一直在。
- **第四个人：** 一张只剩轮廓的海报，名字涂黑，旁边一行系统小字 `04 / SIGNAL WEAK`；点它显示 `NO SIGNAL`（预留了 `BB.onGhost()` 钩子给之后的结局）。
- **三个彩蛋：** 点 `MODIFIED` 值显示 `OPENED hh:mm:ss`（和 MODIFIED 永远差 3 秒）；翻起档案卡的角，露出同一对订书钉的痕迹；红线尾巴上有一枚可以点的小图钉。
- **输入：** 方向键切换；竖屏左右滑动切换；所有控件有可访问名称；`prefers-reduced-motion` 时去掉视差、微晃、拖动惯性。
- **竖屏（390×844）：** 单列：标题和 `BACK`、海报舞台、编号键、档案卡；内容超出高度时竖向滚动，不出现横向溢出。

## 8. 工具脚本

## 9. 踩过的坑

- **GSAP 会接管并清零 `transform` / `translate` / `scale`。** 任何被 GSAP 动画过的元素，不要再用 CSS 写 `transform`（悬停、居中、按下都会被盖掉）。办法：用嵌套的包装元素，一个元素只让一个系统管；居中用 `left/right + margin:auto`；悬停和按下用 `right/bottom` 的偏移。
- **`gsap.quickTo` 不支持 `scale` 这个简写**，要分别驱动 `scaleX` 和 `scaleY`。
- **`cloneNode` 不复制 canvas 内容**（§4）。
- **背景标签页里 `requestAnimationFrame` 会被暂停**，GSAP 的 ticker 也停；自动化测试时页面不可见，动画就卡在半路。要么保证页面在前台，要么手动 `gsap.ticker.tick()` 推进。
- **无头 Chrome 的虚拟时间**下动画不会走，截图要用真实时间（`tools/shot.mjs`）。
- **叠加层补不了烘焙进图里的缺陷。** 第一版在一张画好的图上叠一层屏幕闪烁，平时发糊，闪起来像色块，噪点还和图里的网点冲突，最后整个放弃。墙脚那条又亮又直的线也一样：叠一层踢脚线能盖住，但让模型**重画底图**才是真正的解法。
- **一个预览窗口里的布局测试**要考虑显示缩放（窗口有 1.5 倍缩放时，一个 16:9 的测试框要缩到 530 像素宽才放得下）。
